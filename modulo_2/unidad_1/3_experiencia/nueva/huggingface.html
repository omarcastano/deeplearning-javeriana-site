Hugging Face

Un “GitHub” de modelos de inteligencia artificial

Para reutilizar una red ya entrenada hay que saber dónde conseguirla. Hoy casi siempre se descarga de Hugging Face, una plataforma abierta donde la comunidad comparte modelos, datos y demos.

ModelosLos pesos ya entrenados

Cientos de miles de modelos que se descargan con una línea de código. Cada uno tiene su ficha (model card): para qué sirve, con qué datos se entrenó y sus límites.

DatasetsLos datos para entrenar

Conjuntos de datos compartidos de imágenes, texto y audio, listos para cargar y usar con el mismo estilo de código.

SpacesDemos que se prueban en el navegador

Pequeñas aplicaciones web donde se prueba un modelo subiendo una imagen, sin instalar nada.

La idea

Así como en GitHub se comparte código, en Hugging Face se comparte el resultado de un entrenamiento: los pesos. Cada modelo se nombra usuario/modelo y esa dirección basta para descargarlo.

Hugging Face

No solo texto: modelos de casi todo

Hugging Face nació con modelos de lenguaje, pero hoy es el repositorio más grande de modelos abiertos en muchas áreas. La visión por computador es una de las más activas.

TextoLenguaje

Clasificar, traducir, resumir, responder preguntas y conversar. Ej.: google-bert/bert-base-uncased

VisiónImágenes

Clasificar, detectar objetos, segmentar y estimar profundidad. Ej.: google/vit-base-patch16-224

AudioVoz y sonido

Transcribir voz a texto, clasificar sonidos, generar voz. Ej.: openai/whisper-base

GeneraciónCrear imágenes

Producir imágenes nuevas a partir de una descripción escrita. Ej.: stabilityai/stable-diffusion-xl-base-1.0

MultimodalTexto + imagen

Relacionar lo que dice un texto con lo que muestra una imagen. Ej.: openai/clip-vit-base-patch32

Y másOtras áreas

Series de tiempo, video, biología, robótica. Todo comparte el mismo sitio y la misma forma de descargarse.

En este curso nos interesa la fila de visión: son las redes convolucionales (y primas cercanas) listas para reutilizar.

Hugging Face

Por qué se volvió el estándar

No es solo la cantidad de modelos. Cambió la forma de trabajar: antes cada autor publicaba su código a su manera; ahora hay un formato común.

Todo en un lugarBuscar, comparar, descargar

Se filtra por tarea (por ejemplo, clasificación de imágenes), se ordena por descargas y se lee la ficha de cada modelo.

Misma interfazCambiar de modelo = cambiar un nombre

Modelos muy distintos se cargan igual. Probar otra red es cambiar el texto usuario/modelo.

AbiertoPesos y licencias visibles

Muchos modelos son abiertos: se pueden descargar, estudiar y adaptar. La licencia aparece en la ficha.

AhorroNo hay que entrenar desde cero

Alguien ya gastó los datos y el cómputo. Nosotros partimos de sus pesos: es exactamente transfer learning.

Las librerías: del Hub a tu código

El Hub guarda los modelos; para usarlos en Python se instalan unas pocas librerías de Hugging Face que trabajan encima de PyTorch.

transformersCargar modelos

Descarga un modelo del Hub y lo deja como un módulo de PyTorch. Es la que usamos en el notebook, aunque su nombre sugiere texto, también sirve para visión.

datasetsCargar datos

Descarga y prepara conjuntos de datos del Hub con pocas líneas.

diffusersGenerar imágenes

Modelos que crean imágenes nuevas a partir de texto.

peft y accelerateEntrenar con pocos recursos

Adaptar modelos grandes cambiando pocos parámetros y entrenar en varias GPU. Solo se mencionan; no se usan en esta unidad.

Para nosotros

Un modelo del Hub es un módulo de PyTorch: se entrena con el mismo ciclo que ya conoces (forward, pérdida, backward, step).

Modelos de visión que ya puedes usar

Varias redes del curso están en el Hub, junto con otras más modernas. Todas se descargan igual.

La red con conexiones residuales que vimos en la presentación anterior. Es la que usamos en el notebook.

VGGtimm/vgg16.tv_in1k

Bloques regulares de filtros pequeños, también vista antes. Disponible en el Hub por la librería timm.

Una red convolucional moderna: la misma idea de convoluciones, con ajustes de diseño recientes.

ViTgoogle/vit-base-patch16-224

Vision Transformer: corta la imagen en parches en lugar de usar convoluciones.

Lo importante

Aunque por dentro sean muy distintas, todas reciben una imagen y entregan predicciones o características. Por eso el mismo código de transfer learning funciona con cualquiera de ellas.

Cargar un modelo para entrenarlo

pipeline sirve para usar el modelo tal cual. Para seguir entrenándolo se cargan por separado el procesador y el modelo, que luego se tratan como cualquier módulo de PyTorch.

from transformers import AutoImageProcessor, AutoModel MODEL_NAME = "microsoft/resnet-50" # usuario/modelo en el Hub image_processor = AutoImageProcessor.from_pretrained(MODEL_NAME) model = AutoModel.from_pretrained(MODEL_NAME)
from_pretrained

Descarga el modelo la primera vez y lo guarda en el computador: las siguientes veces carga la copia local.

Procesador

Trae la receta exacta con la que se prepararon las imágenes de entrenamiento: tamaño y normalización. Así no se escribe a mano.

Auto…

Las clases Auto leen la configuración del modelo y eligen solas la arquitectura correcta. Cambiar de red es cambiar el nombre.

Del Hub al transfer learning

Ya sabemos dónde están los modelos y cómo cargarlos. Falta usarlos para una tarea propia: es el mismo transfer learning de la presentación anterior, con el modelo traído del Hub.

1 · Elegir

Se busca en el Hub un modelo de visión adecuado y se lee su ficha: con qué datos se entrenó y qué licencia tiene.

2 · Cargar y congelar

Se carga el modelo con su procesador y se congelan sus parámetros para conservar lo que ya aprendió.

3 · Añadir y entrenar

Se agrega un clasificador nuevo con las clases propias y se entrena con el ciclo de siempre.
